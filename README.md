# E-Commerce Sales Trend Analysis, Revenue Prediction & Interactive ML App

An end-to-end Python data analytics and machine learning project that transforms synthetic e-commerce sales data into business insights, trains a Decision Tree Regression model to predict order revenue, and provides an interactive Streamlit web application for real-time predictions.

## Project Overview

This project combines three major components:

1. **Data Analytics:** Explore sales performance, customer segments, products, regions, and revenue trends.
2. **Machine Learning:** Train and evaluate a Decision Tree Regression model using Scikit-Learn.
3. **Interactive Web Application:** Deploy the trained model through Streamlit so users can enter order details and receive estimated revenue.

The project demonstrates a complete workflow, from synthetic data generation and exploratory analysis to model persistence, interactive inference, and cloud deployment.

## Project Objectives

- Generate and validate a synthetic e-commerce sales dataset.
- Perform data cleaning and feature engineering.
- Calculate important business performance indicators.
- Analyze monthly and quarterly revenue trends.
- Identify high-performing products, categories, regions, and cities.
- Perform basic customer segmentation.
- Generate pivot tables and business visualizations.
- Train a supervised machine learning model to predict order revenue.
- Evaluate model performance using MSE, RMSE, MAE, and R².
- Save the trained model using Joblib.
- Build an interactive Streamlit application with sliders and dropdowns.
- Deploy the application online using Streamlit Community Cloud.

## Dataset Description

The dataset is generated programmatically using Python, NumPy, and Pandas.

- Number of order records: 10,000
- Number of original columns: 14
- Unique customers: Up to 1,500
- Product categories: 5
- Regions: 4
- Order statuses: Completed and Cancelled
- Date range: January–December 2025

### Dataset Features

| Column | Description |
|---|---|
| `Order_ID` | Unique order identifier |
| `Order_Date` | Order placement date |
| `Customer_ID` | Customer identifier |
| `Product` | Product purchased |
| `Category` | Product category |
| `Quantity` | Number of units ordered |
| `Unit_Price` | Price per unit |
| `Discount` | Discount rate applied |
| `Revenue` | Revenue recorded for the order |
| `Profit` | Estimated profit |
| `Region` | Sales region |

The product categories are Electronics, Clothing, Home & Kitchen, Beauty, and Books.

**Data disclaimer:** This is a synthetic dataset created for educational purposes. Its results should not be interpreted as verified real-world e-commerce performance.

## Component 1: Synthetic Data Generation

**Script:** `generate_data.py`

This script generates a reproducible e-commerce dataset containing simulated orders, customers, products, discounts, revenue, profit, locations, payment methods, and order statuses.

The generated data is saved as `ecommerce_sales.csv`.

Run the script whenever you need to regenerate the dataset:

```bash
python generate_data.py
```

Regenerating the CSV may change the data used in subsequent analyses and model training.

## Component 2: E-Commerce Sales Analysis

**Script:** `analysis.py`

This component performs end-to-end exploratory data analysis and business intelligence reporting.

### Data Validation and Feature Engineering

- Inspect dataset dimensions and data types.
- Convert order dates to datetime format.
- Check for missing values and duplicate records.
- Extract year, month, month name, quarter, day, and day of week.
- Calculate profit margin.

### Business KPI Analysis

Calculate:

- Total completed orders
- Total revenue and profit
- Number of unique customers and products
- Total quantity sold
- Average order value
- Average profit per order
- Overall profit margin
- Order cancellation rate

Completed orders are used for sales performance analysis, while cancellation rate is calculated using all generated orders.

### Sales Trend Analysis

Analyze revenue, profit, quantity, and order counts across months and quarters.

The analysis identifies the highest- and lowest-revenue months and the best-performing quarter.

### Product and Category Analysis

- Compare revenue and profit by category.
- Identify the highest-revenue product.
- Rank products by revenue.
- Examine product performance across regions.

### Regional and City Analysis

- Compare revenue and profit across East, West, North, and South.
- Rank cities by revenue.
- Identify geographic areas with stronger sales performance.

### Customer Analysis and Segmentation

Aggregate completed orders by customer to calculate purchase frequency, total revenue, profit, average order value, and most recent order date.

Customers are assigned to four basic segments using median-based rules:

- **High Value:** Higher purchase frequency and spending.
- **Loyal Budget:** Higher purchase frequency but lower spending.
- **High Spending Occasional:** Lower purchase frequency but higher spending.
- **Low Engagement:** Lower purchase frequency and spending.

These are simple rule-based segments, not clusters learned by a machine learning algorithm.

### Payment and Order Status Analysis

Examine revenue and profit by payment method and compare completed and cancelled orders.

### Pivot Tables

Generate summaries for:

- Revenue by product category and region.
- Monthly revenue by product category.

### Visualizations and Output Files

The script generates CSV reports for monthly sales, quarterly sales, category performance, regional performance, product performance, customer analysis, customer segments, payment methods, and cities.

It also saves five charts:

- `monthly_revenue_trend.png`
- `category_revenue.png`
- `regional_revenue.png`
- `top_products.png`
- `customer_segments.png`

Run the analysis:

```bash
python analysis.py
```

## Component 3: Machine Learning Revenue Prediction

**Script:** `ml_model.py`

This component trains a Decision Tree Regression model to estimate order revenue.

### Model Workflow

1. Load `ecommerce_sales.csv`.
2. Filter for completed orders.
3. Select the input features and target variable.
4. Encode categorical features using One-Hot Encoding.
5. Split the data into training and testing sets.
6. Train a Decision Tree Regressor.
7. Generate predictions for the test set.
8. Evaluate model performance.
9. Save the trained preprocessing-and-model pipeline using Joblib.
10. Export actual and predicted revenue to a CSV file.

### Input Features

- `Quantity`
- `Unit_Price`
- `Discount`
- `Category`
- `Region`
- `Payment_Method`

### Target Variable

`Revenue`

### Model Configuration

| Parameter | Value |
|---|---|
| Algorithm | Decision Tree Regression |
| Maximum tree depth | 8 |
| Test set proportion | 20% |
| Random state | 42 |
| Preprocessing | One-Hot Encoding for categorical variables |
| Model persistence | Joblib |

### Evaluation Metrics

| Metric | Purpose |
|---|---|
| MSE | Measures the average squared prediction error |
| RMSE | Measures prediction error in revenue units |
| MAE | Measures the average absolute prediction error |
| R² | Measures the proportion of target variance explained by the model |

The model saves the trained pipeline as `revenue_model.joblib` and exports test-set predictions to `revenue_predictions.csv`.

Run the training script:

```bash
python ml_model.py
```

## Component 4: Interactive Streamlit Web Application

**Script:** `app.py`

The Streamlit application provides a simple user interface for interacting with the saved machine learning model.

### Application Features

- Interactive sliders for quantity, unit price, and discount.
- Dropdown menus for category, region, and payment method.
- A prediction button to estimate order revenue.
- A result display showing the estimated revenue in Indian rupees.
- An optional comparison between the model prediction and the direct revenue formula.
- A cached model-loading function to avoid repeatedly loading the model during normal app interactions.
- Error messages when the model file is missing or a prediction fails.

### How Predictions Work

The application collects the user's order details and constructs a DataFrame with the same feature names used during model training.

The saved Scikit-Learn pipeline applies the required preprocessing and passes the transformed input to the trained Decision Tree Regressor.

The predicted revenue is then displayed in the application.

The app uses the model saved in `revenue_model.joblib`. Train and save the model before launching the app.

## Installation and Setup

### Prerequisites

- Python 3.10 or later
- Visual Studio Code or another Python IDE
- Git and a GitHub account for deployment

### Step 1: Open the Project

Open the `Sales-Trend-Analysis` folder in your terminal or VS Code.

### Step 2: Install Dependencies

Install the packages listed in `requirements.txt`:

```bash
python -m pip install -r requirements.txt
```

### Step 3: Generate the Dataset

```bash
python generate_data.py
```

### Step 4: Run the Sales Analysis

```bash
python analysis.py
```

### Step 5: Train and Save the ML Model

```bash
python ml_model.py
```

Confirm that `revenue_model.joblib` is created successfully.

### Step 6: Launch the Streamlit Application

```bash
python -m streamlit run app.py
```

Streamlit normally opens the application in your browser at:

```text
http://localhost:8501
```

Change the input values and click **Predict Revenue** to test the application.

## Deployment with Streamlit Community Cloud

The application can be deployed online using Streamlit Community Cloud.

1. Upload the project to a GitHub repository.
2. Ensure `app.py`, `requirements.txt`, and `revenue_model.joblib` are available in the repository.
3. Visit [Streamlit Community Cloud](https://share.streamlit.io/).
4. Sign in with GitHub.
5. Create a new app and select the repository and branch.
6. Set the main file path to `app.py`.
7. Deploy the application.
8. Open the generated public URL and test the interactive predictions.

Keep the trained model file accessible to the deployed application. If the app cannot find `revenue_model.joblib`, model loading and predictions will fail.

### Deployment Notes

- Include the saved model in the repository when it is required by the app.
- Do not commit secrets, credentials, or private information.
- Use compatible Python and package versions if deployment encounters dependency errors.
- A `.gitignore` file may be used to exclude temporary files, virtual environments, and unnecessary generated artifacts.

## Limitations

- The dataset is synthetic and may not reflect real customer behavior.
- Customer IDs are randomly assigned to orders, so customer segments may not represent realistic long-term purchasing patterns.
- Revenue is directly calculated from quantity, unit price, and discount in the generator.
- These inputs contain much of the information used to calculate the revenue target, so strong model performance does not demonstrate genuine real-world forecasting ability.
- The model evaluates held-out synthetic orders, not future sales from a real business.
- The app's output is an estimate produced by the trained model, not a guaranteed transaction value.

This project demonstrates the mechanics of model training, persistence, inference, and deployment rather than a production-ready forecasting system.
